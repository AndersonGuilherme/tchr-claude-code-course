# Aula 48 — Próximos passos: evoluindo como desenvolvedor com IA

**Módulo 8 · 5 min · Entrega:** plano de prática e checklist reutilizável para o próximo projeto.

## Antes de gravar

Abra a página inicial do laboratório HTML, a aplicação Next local e, se de fato publicado, o endereço da demo somente leitura. Não apresente uma hospedagem não realizada como conclusão. Prepare checklist final para copiar na plataforma Tchr.

## Roteiro de gravação

### 0:00–0:30 · Gancho · A/C

**Fala:** “Começamos com uma mudança num botão e chegamos a uma aplicação com interface, API, banco e testes. Mais importante que decorar comandos é conseguir explicar o problema, acompanhar as mudanças e comprovar o resultado. Vamos transformar isso no seu próximo passo.”

### 0:30–1:35 · Entenda o que foi aprendido · B/C

[Mostre antes/depois, com legendas claras de laboratório e projeto final.]

**Fala:** “Você aprendeu a preparar o ambiente, escrever instruções, escolher contexto, planejar, revisar e usar ferramentas externas. Também viu que um arquivo de regras não garante obediência, um agente pode errar e uma resposta confiante não substitui um teste.”

“No projeto final, persistência veio do servidor e do banco. A demo pública é somente leitura porque não implementamos contas de usuário. Reconhecer essa limitação faz parte de uma entrega responsável, não diminui o aprendizado.”

### 1:35–3:25 · Veja: checklist para o próximo projeto · B

[Crie ou mostre `CHECKLIST-NOVO-PROJETO.md` no laboratório; leia conectando cada item à sua finalidade.]

```markdown
- [ ] Sei qual problema resolver e o que comprova a entrega.
- [ ] Confirmei pasta, estado do Git e permissões.
- [ ] Li instruções e comandos reais do projeto.
- [ ] Registrei limites e decisões essenciais.
- [ ] Fiz a menor mudança coerente e revisei o diff.
- [ ] Testei casos felizes, erros e regressões relevantes.
- [ ] Separei segredos, dados fictícios e ambientes.
- [ ] Declarei o que não foi executado ou implementado.
- [ ] Tenho histórico recuperável e documentação suficiente.
- [ ] Antes de publicar, revisei acesso, operação e limites.
```

**Fala:** “Se um item não se aplica, explique por quê. Não transforme a lista em uma coleção de marcas verdes sem evidência. Para desenvolvedores, ela pode entrar no template de contribuição; para iniciantes, pode guiar sua próxima prática.”

### 3:25–4:25 · Pratique: plano de evolução · A/B

**Fala:** “Escolha um próximo objetivo, pequeno e real. Para quem está começando: aprenda HTML semântico, eventos JavaScript e Git com um projeto de uma tela. Para quem já desenvolve: aprofunde testes, observabilidade, autorização e revisão de arquitetura.”

“Uma evolução possível é transformar a demo em um aplicativo privado. Mas não comece liberando o botão: primeiro estude autenticação, autorização por usuário e isolamento dos dados, e escreva os testes dessas fronteiras. Outra opção é melhorar acessibilidade com verificação manual e ferramentas especializadas.”

### 4:25–5:00 · Confira e encerramento · A

**Fala:** “Seu exercício final é escolher uma melhoria, escrever critérios e marcar um momento para conferir o resultado. Uma boa resposta tem escopo pequeno e evidência. Você não precisa saber tudo para continuar; precisa saber reconhecer o que entende e o que ainda precisa investigar. Obrigado por acompanhar a Tchr. Use a IA como parceira de trabalho e mantenha a responsabilidade pelas decisões e pelo software que entrega.”

## Solução e encerramento editorial

Plano mínimo: uma meta, dois critérios, fontes de estudo e uma verificação executável. Duração do curso continua estimada até a edição final. Não anunciar autenticação, escala ou cobertura de testes que o curso não entregou. [Referências](../materiais/REFERENCIAS.md).
